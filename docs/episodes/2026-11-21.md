# 都市計画局活動日誌 — 2026年11月21日

*施設配置の相談が、都市開発プロジェクトになった日。*

> この文章は、スクロール動画で確認できた会話と、その後のチャットで整理した内容を基にした**再構成記事**。逐語録ではなく、確認できない発言を引用文として創作していない。

## 1. ただの施設配置の相談だった

Townshipで工場が増え、どこに何を置くかが課題になった。話は個別施設の置き場所から、農業・畜産、農畜産加工、食品製造、一般工業、鉱工業という分類へ進む。山際は農業、鉱山周辺は鉱工業、貨物線沿いは一般工業。街に「用途」が生まれた。

## 2. ジャム工場は、すぐには動かさない

食品加工地区の配置検討では、ジャム工場などの移転を一度止め、地区全体の配置を見直す話になった。一棟を動かせば別の空き地が必要になる。計画局は理想の配置だけでなく、実際に施工できる順序を考えなければならない。

## 3. 市長と都市計画局、そして施工担当

AIが案を出し、市長が判断し、ゲーム内で施工する。会話の中で役割が分かれ、施工担当という「別人格」まで登場した。ゲームの街に、いつの間にか行政と工事体制ができていた（笑）。

## 4. 第2工区は貨物駅周辺へ

貨物線沿いの一般工業地区を対象に、工場の配置だけでなく産業道路、中央分離帯の植栽、空港との境界、将来用地を検討。道路と景観まで整えるうちに、工場の寄せ集めではなく「産業地区の街並み」になっていった。

## 5. なぜかSprintとGitが登場

区切りごとに整備を進めていたら、ソフトウェア開発の言葉が自然に登場した。

```bash
git commit -m "feat: 貨物駅周辺産業地区の整備完了"
git tag township-sprint2-v1.0
```

このときは街づくりをGitに見立てた冗談。しかし、計画・施工・レビュー・完了確認という進め方には確かに共通点があった。

## 6. 街の全景が見たくなる

市長が複数のスクリーンショットを提供し、街全体を一枚で見渡そうと試みた。画像の位置合わせは難しく、追加画像も投入。最終的にAI生成による全景イメージが生まれた。ただし、これは正確な接合地図ではない。

そこで「全景イメージを案内図に、元のスクショをエリア別詳細図にする」という発想が生まれた。全体像と現場の正確さを両立する、都市計画らしい資料構成だった。

## 7. 冗談が本物のリポジトリになる

都市基本計画、整備記録、スクショ、判断の経緯。管理したいものが揃ったことで、GitHubを使う意味が生まれた。市長は実際に `togawa0428/township-urban-development` を開設した。

そしてGitHub Pagesで日誌を公開する構想まで広がる。ChatGPTの会話ログが一次記録であり、GitHubはそこから整理した公式記録、公開サイトは読み物の入口になる。

## 8. 今日の結論

**GitHubを使うために開発プロセスを作ったのではない。開発プロセスが生まれたから、GitHubを使う意味ができた。**

ちなみに、まだゲームである。
