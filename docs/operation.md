# 都市開発プロジェクトの運営

## 役割

- **市長**：整備方針の採否、優先順位、最終承認。実際のゲーム操作を担う。
- **AI都市計画局**：現状分析、土地利用計画、配置案、代替案、記録案の作成。
- **施工担当**：ゲーム内の配置変更や道路整備を実施する、会話上の役割・キャラクター。

## 記録の流れ

1. スクショと会話で現状を把握する。
2. 計画局が整備案を提示し、市長が判断する。
3. ゲーム内で施工し、整備後のスクショを残す。
4. Sprintの区切りで `development-history.md` を追記する。
5. 経緯が面白い回は `docs/episodes/` に活動日誌を残す。
6. 基本方針が変わった場合のみ `master-plan.md` を更新する。

## GitHub運用

- 小さな誤字・画像追加はmainへの直接コミットでもよい。
- まとまった都市計画の追加は作業ブランチを作り、Pull Requestで変更内容を確認する。
- **Commit**：文書・画像の変更を保存する。**Pull Request**：mainへの取り込みを提案・レビューする。**Merge**：承認済みの変更を統合する。
- **Tag**：Sprint等の区切りに付ける。実際のコミットを指すタグのみ作成する。
- コミットの例：`docs: Sprint 2の整備記録を追加` / `feat: 海岸地区の整備結果を追加`
- 過去のゲーム内作業に対して、存在しなかったGitコミットを捏造しない。

## 軽量運用

全施設の細かな移動を逐一記録する必要はない。ゲームを楽しむことを優先し、Sprintや大きな方針変更でまとめる。
